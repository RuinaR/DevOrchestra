# 현재 상태

**P2.81 등록 프로젝트의 선언형 GUI 시나리오.** Controller가 등록된 작업 복제본의 `gui-test.json` 해시, 프로젝트 개정, 역할 예산과 시스템 실행기 해시를 승인에 묶는다. Developer·Reviewer·Verifier의 소유자 승인 실행과 Manager의 영수증 열람 경계를 적용한다. 프로젝트별 합성 입력과 컨트롤 별칭으로 실제 WinForms 창을 검증하고 P2.80 이미지 보고서와 Job 회수를 재사용한다. 임의 프로젝트 EXE·빌드 명령과 모델 호출은 아직 차단된다.

**P2.80 고정 GUI Verifier.** 소유자가 승인한 고정 WinForms 시나리오를 Controller가 실행한다. Job에 편입한 PowerShell의 PID, UI 스레드, 최상위 창을 확인한 뒤 대상 컨트롤에만 제한된 Win32 메시지를 전달한다. 클릭·입력·스크롤·리사이즈 관측과 종료 코드·Job 회수·이미지 해시를 원장에 연결한다. Command Center에서 대표 3장과 원본·가공본·전후 비교를 확인할 수 있다. 승인된 테스트의 고정 데이터에 한정되며 프로젝트 EXE 실행, 모델 역할의 GUI 도구, 실자동 App Server는 여전히 차단된다.

**개발 노트북 복원 기준.** 시작 당시 로컬과 원격 `main`은 `fedace58d14b0efcf52f1182189e8ad266511102`로 일치했고 작업 트리는 깨끗했다. 복원된 EXE는 이전 소스 개정의 산출물이다. 공개 기본 지침은 감독형 요청의 계약 해시에 연결되며 작업 지침 화면에서 확인할 수 있다. 기존 운영 원장과 개인 지침 버전은 보존했다. 작업 소유 Tk 창에서 실제 입력·스크롤·리사이즈·캡처·종료를 확인했다. 이 결과의 범위는 직접 QA이며 Controller 역할별 GUI 도구와 실자동 App Server는 `BLOCKED`다.

**P2.78.** 일반 모드는 승인된 구독 인증·공식 제공자 연결·작업 범위 내 도구 사용을 전제로 한다. 완전 오프라인 실증, Windows 게스트 및 강화 A/B/C는 별도다. 일반 모드에서도 다른 앱 접근 및 범위 밖 파일·명령을 막는 집행, 단일 슬롯·회수·감사가 필수다. Windows Codex 샌드박스의 명령·자식 네트워크 정책은 App Server 호스트 연결 제한의 증거로 사용하지 않는다. 안정판 App Server 자동 턴은 해당 호스트 제한과 부작용 도구 통제를 입증할 수 없어 보류한다. 동일한 오프라인 설정 시험을 다음 필수 단계로 반복하지 않는다.

현재 사용할 방식은 기존 구독 Codex에 지시를 직접 전달하는 감독형 개발이다. 대기 중 구현·검토·검증 지시를 원장에 새 요청을 만들지 않고 다시 열 수 있다. 구현 지시를 다시 열 때는 승인했던 Manager 결과 JSON이 필요하다. 검토 지시는 보존된 변경 증거로 복원되며 원시 Developer 보고서는 저장하지 않는다. [공식 Windows 샌드박스](https://learn.chatgpt.com/docs/windows/windows-sandbox) · [비대화형 CLI](https://learn.chatgpt.com/docs/non-interactive-mode)

**P2.75.** 다음 자동 Manager 후보는 공식 안정판 Codex App Server다. 공식 0.167.0 릴리스를 다음 호환성 검토 대상으로 정했으며 다운로드·설치·실행은 별도 승인이다. 고정 알파 경로는 기존 증거와 함께 보존한다. 새 후보의 승인 SHA-256은 요청과 원장에 귀속되며 후보 실행 경계는 해당 SHA별로 판단한다. 자동 전환은 없다.

| 후보 | 비교와 결정 |
|---|---|
| 고정 App Server 알파 | ChatGPT 계정 확인, 읽기 전용 스레드, 구조화 결과·사용량 이벤트·승인 인터페이스, 소유 Job 회수 코드를 재사용할 수 있다. 이 빌드의 서버 측 부작용 도구 통제와 호스트 연결 제한은 미입증이다. |
| 비대화형 `codex exec` | 구독 인증과 읽기 전용 모드 및 JSON 출력을 지원한다. 별도 프로세스 회수와 이벤트 파싱은 가능하지만 이번 Controller에 필요한 계정·스레드 정책 확인과 대화형 승인 경로를 다시 연결해야 하며 호스트 연결·도구 통제를 해결하지 않는다. |
| 별도 승인 공식 안정판 App Server | 기존 역할·원장·권한 확인·Job 전송기를 재사용한다. 각 빌드가 계약을 그대로 충족하는지 확인해야 한다. Manager 이후 Developer의 작업 폴더 쓰기, 명령 승인, Reviewer·Verifier와 실제 사용량 표시는 아직 미연결이다. |

후보에서도 구독 계정만 허용하고 별도 Responses API·API 키·자동 폴백은 차단한다. 승인된 개인 전역·역할 지침은 전송 전 해시를 확인한다. 첫 모델 턴은 후보의 호출 전 부작용 차단과 공식 제공자 연결 제한이 확인된 뒤 별도 승인한다. [공식 안정판](https://github.com/openai/codex/releases/tag/rust-v0.167.0) · [App Server](https://learn.chatgpt.com/docs/app-server) · [비대화형 CLI](https://learn.chatgpt.com/docs/non-interactive-mode) · [구독 인증](https://learn.chatgpt.com/docs/auth)

**P2.74.** 개발 시작에서 등록 요구사항을 읽어 일반 Manager 준비 상태와 모델·예산 상한을 표시한다. 입장 판정은 필수 경계, 현재 사용자 승인, 고정 CLI 신원을 순서대로 확인한다. 고정 백엔드에 부작용 도구 호출 전 통제와 공식 제공자 연결 제한을 입증하는 신뢰 경로가 없어 실제 상태는 `BLOCKED`다. 합성 근거는 이 상태를 해제하지 않는다. 감독형 Codex 작업은 같은 화면에서 계속 사용할 수 있다. VM과 강화 격리 A/B/C는 일반 Manager 판정에 포함하지 않는다.

**P2.72.** 스레드 전용 검증 경로는 설정 확인과 읽기 전용 스레드 시작에서 멈춘다. 계정·턴 RPC 없이 끝난 합성 시험은 실제 호스트 연결 제한의 증거가 아니다. 실제 턴 경로는 ChatGPT 계정과 OpenAI 인증이 필요한 제공자 응답을 함께 확인하고, 전송 전 설정 및 턴 템플릿 해시를 재확인한다. 자동 모델 입장 차단은 유지한다.

다음 단일 실측은 이미 외부 연결 차단이 검증된 환경에서만, 고정 CLI와 자격증명 없는 독립 합성 홈·작업 폴더·원장을 사용해 수행한다. 설정 확인, 읽기 전용 `thread/start` 1회 및 소유 Job·파이프 회수가 범위다. 계정 조회, 로그인, 턴, 도구 실행은 제외한다. 해당 결과는 스레드의 프로토콜·종료 증거에 한정한다. 첫 모델 턴에는 공식 제공자 연결 제한과 모델 도구의 호출 전 권한 통제가 추가로 필요하다.

**P2.71.** 0.2.70 운영실을 유지하고 고급 정보에 세로 스크롤바, 휠, 키보드 탐색을 연결했다. 표 제목은 호버·누름에도 어두운 배경을 사용한다. 실제 GUI 렌더링은 미검증이다. 자동 Manager는 구독 계정 확인과 읽기 전용 스레드 검증을 거쳐 턴으로 진행하는 기존 계약을 유지한다. 스레드 경계 검증을 턴과 분리하여 합성 피어에서 인증·턴 호출 없이 종료까지 확인했다.

다음 최소 실측 후보는 승인된 합성 작업 폴더와 자격증명 없는 별도 홈에서 공식 고정 CLI의 읽기 전용 스레드 시작 1회다. 먼저 호스트 연결 차단을 검증하고, 설정 조회 후 스레드 정책·지침 출처와 소유 Job·파이프 회수를 확인한다. 모델 턴, 인증, 도구 실행은 범위 밖이다. VM은 선택적 강화 격리이며, 일반 모드에도 실제 실행 전 필요한 파일·프로세스·네트워크 및 도구 경계 증거는 필요하다.

**0.2.70.** 개발 운영실에 목표·완료 기준·최근 요구사항·다음 행동을 배치했다. 감독형 Codex 단계와 가능한 버튼을 현재 인계 상태에 따라 표시한다. 자동 실행은 계속 차단된다. 일반 모드는 승인된 프로젝트·작업 폴더를 대상으로 하며, 메이플스토리 등 다른 앱의 입력·창·프로세스·메모리·화면에는 관여하지 않는다. OS 비간섭 실측은 `NOT VERIFIED`다.

**P2.69.** 다크 화면과 감독형 개발 진입을 정리하고, 다중 완료 기준·여러 줄 목표·요구사항 작성 및 미리보기를 추가했다. 개인 기본 지침은 매니페스트에 귀속된 로컬 참조와 해시를 사용한다. 개정 이력은 유지되며 해당 파일이 바뀐 경우 이전 본문은 확인 불가로 표시한다.

**P2.68.** 초기 저장소 조회 순서와 원장 오류 화면의 창 닫기를 수정했다. 기본 지침, 폼 기반 프로젝트 등록, 승인된 개발용 작업 폴더 복사, 고급 정보 접기를 추가했다. 격리된 실제 GUI 실측은 별도다.

**P2.66.** 감독형 작업은 복제본 기준 캡처 → 변경 파일 검증 → Reviewer JSON → Verifier 빌드 계획·영수증·산출물 확인까지 연결했다. Git은 HEAD·참조·인덱스의 동일성을 확인하고, 작업 트리는 기준 대비 파일 해시로 비교한다. Git 명령은 실행하지 않는다. 외부 제출은 실행 증거로 승격하지 않아 `USER_TEST_READY`는 신뢰 가능한 실행 영수증 발급 경로가 연결될 때까지 차단한다. 포터블 x64 빌드 스크립트를 추가했으며 현재 환경에서는 `PYINSTALLER_NOT_INSTALLED`로 EXE 생성이 차단됐다.

**P2.65.** 감독형 Codex의 Manager 지시·결과 가져오기·질문·Developer 초안을 연결했다. 원장에는 요청 귀속과 결과 해시를 남기며, 요구사항 본문과 전체 프롬프트·계획은 복제하지 않는다. 사용자 가져오기는 외부 실행 미검증으로 표시한다. Developer 변경 증거 가져오기와 실제 Reviewer·Verifier 검증은 미연결이다. 감독형 대기는 합성 개발 주기의 무진척 횟수에 포함되지 않는다. 자동 App Server 모델 실행은 기존 `BLOCKED`다.

**P2.64.** Manager 계획 계약과 합성 세션의 진척·재계획·중단을 연결했다. Command Center는 합성 구현 및 검증의 전후 상태와 연속 무진척 횟수를 표시한다. 실제 요구사항 상태는 합성 결과로 승격되지 않는다. 실제 Reviewer 실행, 사용자 테스트 인계 및 첫 Manager 모델 턴은 기존 차단 상태를 유지한다.

**P2.63.** `IMPLEMENTED`는 프로젝트·요구사항 등록, 기준본 고정, 질문과 다음 단계 안내다. `SYNTHETIC_PASS` 범위는 등록 → 합성 역할 순차 실행 → 결과 확인 → 개선 문서 등록 → 다음 기준본 반영이다. Command Center에서 기준본에 아직 반영되지 않은 개정 수와 Manager 요청의 기록 상태를 확인할 수 있다.

MVP 자동 개발의 `LIVE_PASS`는 아직 없다. Manager 실행은 `GENERAL_ADMISSION_UNVERIFIED` 및 `MANAGER_PRE_EXECUTION_BOUNDARY_UNVERIFIED`로 차단된다. Developer 파일·명령 실행과 실제 Reviewer·Verifier 영수증은 미연결이며, 사용자 테스트 인계에는 신뢰할 수 있는 실제 검증 영수증이 필요하다. [MVP 순서](ARCHITECTURE-ROADMAP.md#p263-실사용-mvp-순서)

최종 사용자 흐름을 정의하고 Command Center에 프로젝트 폴더 선택 및 요구사항 문서 등록을 연결했다. 카탈로그의 문서 버전과 합성 실행에 고정된 버전을 구분한다. 실제 자동 개발과 사용자 테스트 인계는 아직 차단 또는 미구현이다. P2.44의 사전검사 증거는 이력으로 유지하며 파일 경계 재시험은 수행하지 않았다.

P2.38 사용자 PowerShell에서 합성 마커 해시와 원장 READY를 확인했다. 사용자 세션 확인은 해당 체크아웃과 합성 마커에 한정한다. 이전 지침의 원장·내용 검증은 PASS, 새 지침 폴더는 비어 있다. 대상 ACL에 기본 Users 그룹의 상속 Modify 권한이 있어 실제 개인 DB 이전은 BLOCKED다. 개선본 활성화는 별도 승인이다.

P2.37은 명시적 초기화와 GUI 최초 설정 저장을 같은 검증 경로에 연결했다. Codex 셸에서 새 실행 원장과 하위 폴더를 생성해 READY를 확인했다. 사용자 Windows 세션에서 합성 마커를 대조하기 전까지 `HOST_STORAGE_NOT_VERIFIED`다. 이전 지침 저장소는 가져오지 않았다.
