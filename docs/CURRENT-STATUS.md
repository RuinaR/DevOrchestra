# 현재 상태

**WinForms V1 잘림 수정 종단 간 Windows 실증.** 기존 V1 `REWORK`를 독립 시험 복제본에 인계했다. 실제 Codex Developer는 `Fixture.cs`의 마지막 상태에만 적용되던 고정 크기 설정을 제거했다. 새 WinForms EXE의 화면을 받은 Reviewer는 `ENTER → RIGHT → SPACE`를 선택했고, 소유 창에서 세 차례 입력과 네 화면을 확인한 뒤 전체 문구 `Fixture complete`가 표시됐다고 `ACCEPT`했다. 별도 결정적 Verifier는 새 실행에서 첫 세 화면의 라벨과 마지막 전체 라벨의 픽셀 마스크를 동결 참조와 대조해 모두 통과했다. 최종 Manager와 Controller는 C1을 `VERIFIED`, 시험을 `COMPLETED`로 기록했다. 계획 Manager가 시험 실행기의 역할 기준을 초과한 첫 기록은 보존했다. 원장과 대조한 확정 계획을 재사용해 Developer부터 이어갔다. 총 실제 호출 7회, 제공자 사용량 159,917토큰, 두 실행의 경과 시간 합계 136.73초다. 시험 원본 Git 불변, 소유 Job 회수와 두 임시 폴더 제거를 확인했다. 빌드와 독립 픽셀 판정에는 시험 전용 어댑터를 사용했다. Godot 자율 재플레이와 MRGame 적용은 미검증이다.

**WinForms 잘림 수정 종단 간 시험 준비.** 이전 온라인 Reviewer의 V1 `REWORK`와 네 프레임을 검증해 별도 Git 원본·복제본의 기준에 연결했다. Windows 오프라인 독립 검사는 결함 EXE와 정상 참조를 각각 공식 CLI의 오프라인 MXC 소유 Job에서 실행했다. 동일한 세 입력에서 첫 세 상태의 라벨 픽셀 마스크가 일치했고, 마지막 라벨 너비는 결함본 81픽셀과 정상 참조 200픽셀로 구별됐다. 결함본 마지막 프레임은 기존 온라인 프레임과 해시가 일치했다. Controller는 재검토에서 각 행동을 같은 EXE 및 전후 프레임에 연결해 확인하며, 중단 체크포인트에 재작업 근거를 보존한다. 실제 Developer 수정·재플레이·최종 Manager 판정은 온라인 시험 대기 상태다.

**WinForms 소유 창 AI 플레이 · 기대 문구를 고정한 온라인 검증 통과.** 같은 Windows 시험 EXE에서 실제 Codex가 화면을 보고 `ENTER → RIGHT → SPACE`를 선택했다. 소유 창 입력 세 번과 서로 다른 화면 네 장을 대조했다. 첫 턴은 CLI 종료 지연 뒤 소유 Job을 회수하고 확정 응답으로 계속 진행했다. 최종 Reviewer는 기대 문구 `Fixture complete`와 P3에서 보이는 `Fixture`를 대조해 중간 심각도·낮은 불확실성의 잘림 결함 V1을 보고하고 `REWORK`를 반환했다. 실제 모델 호출 4회, 제공자 44,067토큰, 61.80초다. Job은 모두 회수했다. 최초 임시 폴더 정리 미확인 기록을 유지하고, 시험용 Git 개체 세 개의 읽기 전용 속성을 처리한 뒤 폴더 제거를 확인했다. MRGame과 자동 수정·재빌드 실증은 이번 범위에 포함되지 않았다.

**WinForms 소유 창 AI 플레이 · 온라인 3단계 및 지연 회수 통과, 시각 결함 탐지 실패.** 동일한 시험 EXE에서 실제 모델이 `ENTER → RIGHT → SPACE`를 선택했고, 같은 온라인 실행에서 소유 창 입력 3회와 서로 다른 화면 4장을 확인했다. 두 번째 턴은 완료 응답 뒤 CLI 종료가 지연됐으나 소유 Job을 회수하고 확정 응답을 다음 입력으로 사용했다. 모델 4회, 제공자 43,921토큰, 54.67초. 최종 Reviewer는 네 화면을 설명하고 `ACCEPT`를 반환했다. 미검증 메모 다섯 건이 이전 파서 한도에 걸려 한도를 8개로 맞춘 뒤 저장된 응답을 재호출 없이 검증했다. 마지막 화면에서 예상 라벨 `Fixture complete`가 `Fixture`로 잘렸지만 모델은 결함으로 보고하지 않았다. MRGame, Godot 게임 플레이와 자동 재작업 실증은 수행하지 않았다.

응답을 완료한 뒤 종료를 지연하는 합성 Windows 프로세스에서 15.22초에 소유 Job을 회수하고 완료 응답과 토큰을 다시 확인했다. 관련 회귀 49건을 통과했다.

**WinForms 소유 창 AI 플레이 · 온라인 재시험 부분 통과.** 독립 Git 시험 복제본에서 구독 모델이 첫 화면에서 `ENTER`, 이어진 화면에서 `RIGHT`를 각각 선택했다. 첫 입력은 온라인 실행 중 소유 창으로 전달됐고 화면 전환을 확인했다. 두 번째 모델은 완료 이벤트를 남겼지만 CLI 종료가 지연되어 360초 한도까지 기다린 뒤 Job을 회수했다. 두 번째 입력과 최종 시각 검토는 실행되지 않았다. 원본 이벤트와 승인된 캡처를 대조해 두 응답 및 21,346토큰을 독립 확인했다. 첫 Git 준비 전 CLI 시작은 신뢰 검사에서 거절돼 모델 턴이 없었다. 이미지 Reviewer는 이제 구조화된 응답과 제공자 사용량이 확인된 뒤 15초간 종료가 지연될 때 소유 Job을 회수하고 확정 응답을 검증한다. 해당 변경의 실제 온라인 재시험은 남아 있다.

**WinForms 소유 창 AI 플레이 · 실제 이미지 이해 1회, 전체 실증 미완료.** 공식 CLI 0.167.1과 구독 모델이 실제 첫 화면의 안내를 읽고 올바른 키를 선택했다. Controller가 CLI 응답 객체에서 메시지를 꺼내지 않아 당시 입력을 거부했고, 다음 시각 검토 요청은 CLI의 지침 파일 읽기 오류(Windows 오류 5)로 턴 완료를 확인하지 못했다. 확인된 사용량은 입력 10,666·출력 78토큰이며 두 번째 요청 사용량은 미확정이다. 응답 처리를 수정했다. 별도 오프라인 실행에서 EXE와 첫 화면의 동일 해시를 대조한 뒤 저장된 모델 응답을 적용해 실제 화면 전환 한 건과 Job 회수를 확인했다. 실제 온라인 3단계 플레이와 최종 시각 판정, 게임 및 자동 재작업은 아직 미검증이다.

**소유 창 AI 플레이 · IMPLEMENTED / SYNTHETIC_PASS.** 새 승인에서 AI 플레이를 켜면 기존 소유 창 브로커와 공식 Codex CLI 이미지 입력을 연결한다. 사이클마다 최대 3회 모델이 한 장의 실제 창 이미지에서 다음 행동을 제안하며, Controller가 좌표·키·시간·창 소유권을 검증하고 새 화면을 기록한다. 별도 WinForms 시험 앱을 공식 CLI의 오프라인 MXC로 실행해 세 차례 입력과 네 장의 서로 다른 화면, 소유 Job 회수를 확인했다. 행동 선택은 모의 응답이었다. 사용자 앱을 대상으로 삼지 않았다. 실제 구독 모델의 행동 선택, Godot 실플레이, 시각 결함의 실제 Developer 수정·재빌드·재플레이는 아직 검증되지 않았다.

**공식 Windows Computer Use · 자동 세션 입력 BLOCKED.** 공식 데스크톱 기능은 활성 데스크톱의 포인터·키보드·포커스를 사용한다. 고정 공식 Windows x64 Codex CLI 0.167.1의 `exec --help`, `app-server --help`와 실험 항목을 포함한 공개 JSON 스키마를 로컬에서 확인했다. Computer Use 설정과 정책 타입은 있었지만 Controller 소유 Windows Job의 창만 대상으로 관측·입력하는 공개 호출은 확인되지 않았다. 계정 설정과 앱 허용 정책은 창 단위 비간섭 증거가 될 수 없다. 이번에는 공식 조작과 온라인 모델 호출을 실행하지 않았다. 기존 브로커의 실제 WinForms 입력·관측, 호출 범위 검증, 취소·시간 초과 후 Job 회수 및 별도 시험 프로세스 생존을 Windows에서 확인했다. 새 시각 검토 기록은 캡처 출처, 시나리오 입력 및 CLI 이미지 검토를 표시하고 자율 플레이는 `NOT_VERIFIED`로 남긴다. **등록 자동 개발 · 대형 소스와 후보 복구.** MRGame의 2사이클 Developer가 정상 종료했지만 기획서가 25,250바이트에 도달해 이전 24,000바이트 공통 제한에 걸렸다. Reviewer와 Verifier는 실행되지 않았다. 새 빌드는 UTF-8 소스 512KiB, 검토 diff 131,072자, 계획 8,000자, 새 일반 세션의 역할 출력 8MiB를 각각 지원한다. 긴 역할 입력은 표준 입력으로 보내 Windows 명령행 길이 제한을 피한다. 일반 세션의 수정 경로 상한은 64개, 선택적 사이클 상한은 200회다. 새 일반 세션의 역할별 소프트 시간 기준은 Developer 7,200초, 그 외 모델 역할 3,600초다. 별도 승인된 등록 원본 반영은 변경 전후 파일 합계 512KiB를 지원한다. 실제 MRGame 복제본은 읽기 전용 재개 검토를 통과했다. 당시 변경 후 해시는 확정되지 않았으므로 새 승인에서 현재 후보의 해시를 고정하고 최초 등록 기준과 비교한 뒤 2사이클 Reviewer·Verifier·최종 Manager를 실행한다. 실제 온라인 재호출은 하지 않았다.

**등록 자동 개발 · 저장된 2사이클 계획 복구.** MRGame의 2사이클 Manager가 승인된 C1과 문서 경로를 선택하고 정상 종료했으나, Controller가 객체 형태의 계획을 문자열과 같은 기준으로 검사해 차단했다. 읽기 전용 재개 검토에서 저장된 계획·Reviewer 재작업 근거·사용량·복제본과 원본 Git·소유 자원 회수 기록을 대조했다. 새 승인 후 같은 복제본에서 2사이클 Developer부터 실행할 수 있다. 실제 MRGame 모델 재호출은 없었다. 새 실행에서는 승인된 구조의 계획을 읽고, 읽을 수 없는 응답은 후보와 재작업 근거를 보존하는 체크포인트로 기록한다. 모델 호출 횟수를 다 쓴 경우 새 계획이나 Developer를 시작하기 전에 안전하게 종료한다.

**등록 자동 개발 · 모델 출력 계약.** 계획 Manager와 텍스트 Reviewer·최종 Manager가 Codex CLI 출력 스키마를 사용한다. Controller는 판정을 다시 해석하고 독립 증거와 대조한다. 확정된 판정 응답이 잘못됐거나 독립 증거와 충돌하면 후보를 보존하고, 새 승인으로 해당 검토 역할부터 다시 실행할 수 있다. 이미지 Reviewer의 응답 형식과 캡처 증거 검증은 유지한다. 새 스키마의 온라인 모델 동작은 이번에 시험하지 않았다.

**등록 자동 개발 · 진척 계산, 재계획과 중단 보존.** 실제 MRGame은 사이클 상한 없이 2사이클의 기획서 변경이 수용됐지만 기능 검사 통과가 없어 이전 규칙에서 `NO_PROGRESS`가 됐다. 수정 후 읽기 전용 검토로 그 기획서를 새 세션에 재사용할 수 있음을 확인했다. 회귀에서 첫 무변경 후 재계획, 두 번째 무진척 후 후보 저장, 기획서 재작업 수용 후 3사이클 진입, 기능 미통과를 유지한 계획 문서 진척과 안전한 상한·예산 체크포인트를 확인했다. 실제 MRGame 모델은 재호출하지 않았다.

**등록 프로젝트 · 처음부터 다시 시작.** 기존 경로가 사라진 Windows 시험 프로젝트에서 Command Center 버튼으로 새 복제본을 생성했다. 원본·이전 작업 파일·감사 기록이 유지되고 새 복제본의 현재 세션에 이전 기록이 표시되지 않음을 확인했다. 실제 MRGame은 읽기 전용 복제 범위 검토까지 확인했다.

**등록 자동 개발 · 판정과 응답 복구.** 실제 MRGame의 첫 사이클에서 Reviewer가 반환한 여러 줄 `REWORK` 응답을 보존 로그와 영수증으로 확인했다. 새 파서로 기존 판정을 읽고 Developer diff, 원본 Git, 후보 해시, 사용량과 Job 회수까지 대조한 읽기 전용 재개 검토를 통과했다. 실제 MRGame은 재개하지 않았다. Windows 오프라인 시험에서는 모의 CLI 응답을 사용해 Reviewer 재사용 후 재작업과, 최종 Manager 응답·Verifier 결과를 재사용한 모델 호출 0회의 완료 처리를 확인했다.

**등록 자동 개발 · 종료 예약과 인계 요약.** Windows GUI에서 모의 모델과 독립 검사로 예약 취소, 체크포인트 저장, 소유 자원 회수, 다음 사이클부터 이어서 개발을 확인했다. 활성 Developer 카드에 Manager가 전달한 계획이 표시된다. 이번 검증에서 새 구독 모델 요청은 수행하지 않았다.

**자동 개발 · 현재 활동과 전체 작업 목록.** 실행 중인 역할 카드에 초록 테두리와 완료 기준, Codex 활동을 표시한다. 별도 작업 창에서 역할 시작·종료, 변경 파일과 도구 활동을 확인한다. Windows GUI 시험에서 모의 CLI 명령이 진행 중일 때 표시와 강조를 확인했고, 세션 종료 후 목록과 강조 해제를 확인했다.

**등록 자동 개발 · 메인 운영실 진행 표시.** 승인 후 설정 창을 닫고 메인 창이 실행과 중단을 관리한다. 실제 Windows Command Center에서 모의 모델 응답과 독립 검증을 사용해 1사이클 Developer 실행, 확정 토큰, 2사이클 최종 완료와 변경 파일 표시를 확인했다.

**AI 시각 검토 · 화면 준비 전 시작.** 등록 개발에서 화면 검사 설정 없이 AI 시각 검토를 승인할 수 있다. 임시 폴더에 실행 가능한 Windows 앱이 없으면 코드만 검토하고 시각 검토는 미확인으로 남긴다. 실제 Windows 오프라인 시험에서 WinForms 후보를 MXC 안에서 실행하고 시작 화면 PNG, Reviewer 첨부 준비, 소유 Job 회수와 복제본 불변을 확인했다. 이 자동 빌드·캡처 흐름을 실제 온라인 세션에서 끝까지 검증하는 작업은 남아 있다.

**AI 시각 검토 · 이미지 이해와 결함 탐지 LIVE_PASS.** 출력 스키마를 적용한 Codex 0.167.1의 구독 Reviewer 한 번에 합성 Win32 소유 창의 452×314 PNG 두 장을 첨부했다. Reviewer는 프롬프트에 없던 두 제목과 파란색에서 초록색으로 바뀐 배경을 구별하고, 양쪽 캡처의 오른쪽 상태 문구 잘림을 V1 중간 심각도·낮은 불확실성 결함으로 보고했다. 키·클릭이 소유 창에 도착했고, 응답 JSON과 프레임 해시를 검증했다. 제공자 보고 사용량은 입력 10,809와 출력 425를 합한 11,234토큰이다. 전체 24.53초에 종료했고, 소유 Job을 회수하고 스테이징을 정리했다. 모델이 직접 수정한 후보의 재빌드·재검토, 결정적 기능 판정 및 실제 게임 통합은 미검증이다.

**AI 시각 검토 · 온라인 합성 Windows 시험 1회.** 소유 Win32 창의 452×314 PNG 두 장을 실제 ChatGPT 구독 Codex 0.167.1 Reviewer에 전달했다. 응답 종료와 제공자 사용량 11,027토큰을 관측했고, 역할과 시험 Job 회수 및 작업 스테이징 정리를 확인했다. 반환값이 시각 응답 계약을 통과하지 않아 이미지 이해와 잘림 탐지는 미확정이다. 초기 CLI 실행은 이미지 인자가 프롬프트를 소비해 모델 호출 전에 종료됐다. 프롬프트 구분자를 추가했고, 후속 시각 호출은 CLI 출력 스키마를 전달한다. 새 스키마를 사용한 온라인 재시험은 대기 중이다.

**등록 프로젝트 AI 시각 검토 · 오프라인 연결 검증.** Command Center의 별도 체크와 최종 승인으로 소유 창 PNG를 기존 읽기 전용 Codex Reviewer 호출에 첨부한다. Controller는 실행 영수증과 PNG 바이트를 연결하고 검토 뒤 다시 확인한다. 시각 결함과 코드 결함을 다음 Developer 작업에 전달하고 시각 판단을 기능 기준의 PASS와 구분한다. 실제 Windows 소유 창에서 키·클릭·화면 변화를 관측했으며, 공식 Codex 0.167.1의 로컬 프롬프트 검사에서 캡처 두 장이 `input_image`로 구성됐다. 손상된 PNG를 거부했다. 온라인 이미지 이해, 실제 모델의 결함 발견·재작업·재검토, 새 Lantern Ruins 플레이와 화면 기반 동적 입력은 미검증이다.

**0.3.0 신규 사용자 검증.** 등록 개발 화면은 로그인이 필요한 경우 공식 연결 화면을 안내한다. Windows 기본 텍스트 검사는 Microsoft 카탈로그 서명을 확인한 System32 도구로 복제본의 파일을 읽어 기대 출력과 비교한다. 재개 검토는 기존 세션과 별도로 시간과 토큰을 입력받는다. 새 계정 로그인과 온라인 개발 검증 결과는 [릴리스 적합성 판정](WINDOWS-RELEASE-QA.md#릴리스-적합성-판정)에 기록한다.

**Windows 일반 사용자 릴리스 후보.** 첫 실행에서 사용자 저장소를 준비한 뒤 공식 ZIP, ChatGPT 로그인, 모델과 한도 조회, 로컬 실행 확인 및 프로젝트 등록으로 이동한다. 등록 개발 시작 화면에 복제본 준비와 승인 경로를 우선 표시한다. 새 포터블 저장소는 사용자 LocalAppData에 있고, EXE 옆에 기존 저장소가 있으면 해당 위치를 계속 사용한다. 다른 Windows 사용자 계정에서의 공식 로그인부터 실제 자동 개발까지는 [릴리스 검증표](WINDOWS-RELEASE-QA.md)에 따른 검증 대기다. 아래 항목은 각 개발 시점의 관측 기록이다.

**Lantern Ruins · 사용자 플레이 및 최종 검토 준비.** Command Center에서 현재 후보와 일치하는 Windows EXE 및 해시를 조회하고, 소유 Job으로 EXE를 실행할 수 있다. 조작 이해도·난이도·화면·진행 흐름·완주 여부와 메모를 EXE에 묶어 비공개 원장에 남긴다. 사용자 관찰은 자동 Verifier 판정과 별도로 유지한다. 실제 EXE의 표시·종료와 Job 회수를 확인했다. 전체 자동 플레이는 이전 내장 팩 실행의 증거이며, 배포 EXE에서의 전체 플레이와 첫 플레이 품질은 사용자 확인이 남아 있다. 검증본 EXE 옆에 Godot 4.7.2의 MIT 및 제3자 고지와 Kenney CC0 파일을 갖췄다. 새 모델 호출이나 원본 반영은 없었다.

**Lantern Ruins · REWORK 후 오프라인 플레이 검증.** 직전 Reviewer와 최종 Manager의 판정·응답 해시는 남아 있으나 실행 스테이징이 정리돼 Reviewer의 상세 지적은 복구할 수 없었다. 독립 점검에서 확인한 결과 화면의 플레이어 겹침과 재시작 시 위험 패턴 시간 기준을 복제본의 `scripts/game.gd`에서 수정했다. Windows x64 EXE를 내보내 소유 창 실행·종료를 확인했다. 별도 검증기는 내보낸 EXE의 내장 팩을 Windows Godot으로 실행하고 키 입력만 사용했다. 실패·재시작 후 세 유물을 중복 없이 얻고 5분 43초에 승리했으며, 다시 재시작했다. 전체 검사 경과는 367.84초다. C2·C3의 해당 경로와 C4의 800×540 화면 및 상태 전이를 확인했다. C5는 시간과 Kenney CC0 출처를 확인했고, 첫 플레이의 난이도·시각 품질 및 배포용 Godot 고지는 검토가 남았다. 동결 기준과 이전 원장은 유지했다. 새 온라인 요청과 원본 반영은 없었다.

**Lantern Ruins · 검토 재개 결과 `REWORK`.** 확정 사용량 252,181토큰을 남긴 Developer의 후보를 새 승인으로 읽기 전용 검토했다. Developer를 재호출하지 않았다. Reviewer와 최종 Manager는 모두 `REWORK`를 판정했다. 독립 Verifier는 Windows x64 EXE 내보내기·실행·창 크기 변경·캡처·종료를 확인했다. C1은 `VERIFIED`, C2–C5는 `USER_TEST_REQUIRED`다. 51.25초 동안 모델을 두 번 호출해 23,116토큰(Reviewer 13,240, 최종 Manager 9,876)을 사용했다. 추가 승인 기준을 초과하지 않았다. 원본과 후보 해시를 재확인했고 소유 Job을 회수했다. 실행 파일·캡처·검증 영수증은 보존했으며 전용 스테이징은 정리했다.

**신규 승인에 적용되는 Graceful Stop.** 기본 소프트 기준은 세션 14,400초·1,500,000토큰, Developer 3,600초·350,000토큰, 계획·최종 Manager 각각 1,200초·120,000토큰, Reviewer 1,200초·150,000토큰이다. 사이클 상한은 선택 사항이다. 기준에 도달하면 `STOP_REQUESTED`를 기록하고 새로운 계획과 개발을 시작하지 않는다. 진행 중인 역할의 확정 결과를 받고, 별도 마무리 예산(최대 1,800초·300,000토큰)에 Reviewer·Verifier·최종 Manager를 실행한다. 역할별 유예 상한은 900초, 이벤트 무응답 제한은 600초(실행 중인 도구가 확인되면 1,200초)다. 마무리 예산이 부족하면 `SIGNOFF_PENDING`으로 후보·diff·확정된 단계 증거를 보존한다. 즉시 중단, 권한 만료, 소유권 미확정 및 `REQUEST_UNKNOWN`에는 별도 중단·복구 계약을 유지한다. 토큰은 Controller의 예약 및 제공자 보고에 근거한다. 이전 승인은 발급 당시 조건을 따른다.

**Lantern Ruins · 기존 Developer `REQUEST_UNKNOWN`, 새 작업 승인 준비.** 계획 재사용 뒤 Developer가 승인 범위의 파일 7개를 수정했다. 300초 역할 제한으로 Job을 회수했고, 도구 종료 이벤트 14건은 있지만 `turn.completed`와 사용량이 없어 역할 완료를 확정할 수 없다. 이전 요청은 재전송하지 않았다. 동일 후보 해시의 별도 Windows EXE 검증에서 실행·정상 종료와 Enter 시작, D 이동, HUD 표시, R 재시작을 확인했다. 설계 문서 누락으로 C1은 실패했고, C2–C5의 나머지 플레이 검증은 `USER_TEST_REQUIRED`다. 후보·원본·Git 상태와 EXE·이미지 해시를 대조하고 새 작업 검토를 원장에 기록했다.

**이전 게임 실행 한도.** 당시 기본값은 세션 7,200초·750,000토큰, Developer 호출당 1,800초·150,000토큰, 계획·최종 Manager 각각 600초·65,000토큰, Reviewer 600초·80,000토큰이었다. 당시 Controller는 역할 시간과 세션 잔여 시간 중 작은 값을 Windows Job 제한으로 사용했다.

**2D 게임 파일럿 · 첫 실제 온라인 세션은 계획 검증에서 BLOCKED.** Command Center 승인 1회로 계획 Manager만 호출했다. 계획은 동결 기준 C5를 선택했고 JSON 형식과 권한 범위는 맞았으나, 1,035자로 당시 1,000자 제한을 넘었다. 실제 호출은 1회이며 20.66초와 22,441토큰(입력 22,083, 그중 캐시 10,240, 출력 358)을 사용했다. 개발 사이클은 0회이며 소스 변경, Reviewer·Verifier·최종 Manager 및 새 EXE는 없다. C1–C5는 모두 `NOT_STARTED`다. 소유 Job을 회수하고 원본·복제본과 복구 자료를 보존했다.

**2D 게임 파일럿 · 이전 계획 재개.** 게임 계획만 1,600자까지 허용하며 기존 동결 기준 ID와 계획 구조를 계속 검사한다. 기존 응답·사용량·계획·복제본 해시를 대조해 1,479초·327,559토큰·추가 모델 최대 7회 범위로 재개했다. 첫 Manager를 반복하지 않고 Developer부터 시작했다. 해당 Developer 요청은 위의 미확정 상태로 남았다.

**2D 게임 파일럿 · 초기 Windows x64 EXE 오프라인 검증 PASS.** 공식 Godot 4.7.2 템플릿 묶음의 SHA-256과 공식 SHA-512를 대조해 프로젝트 전용 Windows x64 릴리스 템플릿을 등록했다. Command Center에서 독립 복제본의 스테이징 사본을 MXC로 내보내고, PCK를 내장한 EXE를 별도 작업 폴더에서 실행했다. 소유 창 표시, 400×255에서 432×279로 크기 변경, 스페이스 키 메시지 전송, 캡처와 정상 종료를 확인했다. 내보내기와 실행은 각각 종료 코드 0이며 Job 활성 프로세스는 0이다. EXE·이미지·로그와 해시를 로컬에 보존했고 다운로드와 중간 스테이징을 정리했다. 이 초기 장면의 검증 범위는 내보내기와 소유 창 실행이었다.

**등록 실행 재개 · 실제 Reviewer·Verifier·최종 Manager 검증.** Command Center에서 `signoff.py` 후보를 360초·추가 120,000토큰으로 승인했다. Developer 호출 없이 Reviewer가 `ACCEPT`를 반환했고 독립 Verifier는 `hello`와 `goodbye`를 각각 종료 코드 0으로 확인했다. 최종 Manager와 Controller의 판정은 `COMPLETED`였다. 모델 2회의 제공자 보고 사용량은 20,623토큰이며 모든 소유 Job이 회수됐다. 최초 종료 영수증은 `CLEANUP_UNVERIFIED`를 유지한다. 동일 실행의 임시 폴더 삭제와 부재 확인은 별도 원장 이벤트에 남겼다. 원본과 후보 복제본은 그대로다.

**공식 CLI Developer 일회 시험 · UNVERIFIED.** 표준 일반 입장은 `GENERAL_ADMISSION_UNVERIFIED`다. 명시 승인된 일회 시험에서 공식 ChatGPT 로그인을 확인했고, 공식 MXC·단일 슬롯·원장·Job을 유지한 채 합성 복제본에서 CLI를 실행했다. 종료 코드 1, 응답·제공자 사용량 UNKNOWN이며 파일 변경은 없었다. 원본·Git 불변과 Job 활성 0을 확인했다. 첫 시험의 `gpt-5.4`는 전용 홈에 생성된 모델 목록에 없었다. 이 사실만으로 실패 원인을 확정할 수 없다. 재실행 전에 별도 승인이 필요하며, 이후 시험은 확인된 모델과 원문을 저장하지 않는 실패 분류를 사용한다.

**단일 일반 개발 모드 확정.** 공식 Codex가 인증·모델 통신을 처리한다. 강화 격리와 독립 OS 송신 제한을 제품 입장에서 제외했다. 기존 계정·WFP·프록시·게스트 자료는 역사 기록 및 복구용으로 보존한다. 원본 반영의 별도 승인과 Controller의 복제본·Job·예산·원장은 계속 적용한다.

**공식 Codex CLI 0.167.1의 로컬 시작 확인.** Job 동시 프로세스 상한 8에서 Windows MXC 파일 도우미 생성이 오류 1816으로 실패했다. 512 MiB 메모리 상한과 MXC·승인 정책을 유지하고 Developer 시험의 동시 프로세스 상한만 16으로 바꾸자 `codex exec`가 `thread.started`와 `turn.started`를 기록하고 소유 루프백에 한 번 도달했다. 로컬 서버가 의도적으로 요청을 거부했으며 복제본·원본 불변과 Job 회수를 확인했다. App Server의 상한 16 대조는 종료 과정에서 시간 초과되어 CLI를 우선한다. 실제 구독 모델 응답, 모델 주도 변경 및 자동 반복은 아직 실측하지 않았다.

**일반 Codex Developer · Windows 명령 경계 관측, 모델 실행 BLOCKED.** `native-command-diagnostic --general-developer`는 승인·Job·단일 슬롯·원장을 재사용하며 계정·모델 RPC를 허용하지 않는다. 서명 확인한 App Server 0.167.1에서 별도 Git 복제본의 고정 명령으로 두 파일을 변경했고 독립 검증 종료 코드는 1에서 0으로 바뀌었다. 복제본 `.git/HEAD`와 합성 원본 쓰기는 오류 5, 명령 IPv4·IPv6 루프백은 10013으로 거부됐다. 그러나 `thread/start`의 지침 탐색용 MXC 파일 도우미가 프로세스 생성 오류 1816을 반환했다. Job 메모리 상한을 512 MiB에서 1 GiB로 바꾼 대조에서도 동일했다. 전용 계정·WFP 없이 검증한 범위는 명령 실행까지다. 구독 인증, 모델 도구, 외부 프로세스 비간섭과 온라인 역할 순환은 미검증이다.

**P2.119 생성 시 Job 편입 · IMPLEMENTED, 동일 SID 제한 토큰 SYNTHETIC_PASS.** 네이티브 시험기의 교차 계정 생성 코드는 `LogonUserW`와 `CreateProcessAsUserW`의 `STARTUPINFOEXW` Job 속성을 사용한다. 재개 전에 Job 소속, 작업자 SID와 비승격 토큰을 확인하고, 생성 후 별도 편입으로 폴백하지 않는다. 비승격 Windows에서 일반 생성 대조군과 현재 SID의 제한 토큰이 각각 재개 전 소속 및 종료 코드 0을 기록했다. 잘못된 토큰은 오류 6으로 거부됐고 Job 생성 기록은 0이었다. 비활성 복구기는 활성 시험의 원장 항목을 거부한다. 전용 계정 생성과 활성 작업자 종료 증거를 사용하는 별도 WFP 복구기는 아직 실측되지 않았다. 이번에는 계정·WFP 정책 설치 및 모델 호출을 수행하지 않았다.

**P2.118 로컬 CONNECT 프록시 · SYNTHETIC_PASS, 실제 Windows 소켓 관측.** 일반 사용자 권한의 Controller 소유 루프백에서 IPv4·IPv6 각각 승인된 합성 업스트림으로 양방향 데이터를 중계했다. 같은 포트에서 비승인 CONNECT와 불일치하는 Host에는 403을 반환했고 두 업스트림에서 연결 미수신을 확인했다. 앞선 호스트 양성 대조군은 두 업스트림에 연결했다. 전용 계정 통합 시험은 기존 교차 계정 실행의 생성 후 Job 편입 구간과 비활성 계정 전용 복구 때문에 시작하지 않았다. 시험 계정·WFP 정책을 설치하지 않았으며 별도 읽기 전용 조회에서 시험 개체의 부재를 확인했다. 계정별 송신·DNS Client 경계와 활성 복구는 계속 미검증이다.

**P2.118 활성 Job 회수 · SYNTHETIC_PASS, 실제 Windows 관측.** 현재 사용자 권한의 독립 시험에서 `CREATE_BREAKAWAY_FROM_JOB` 요청은 오류 5로 거부됐고, 정상 생성한 자식과 작업자가 살아 있는 같은 Job 구성원임을 확인했다. Job 핸들을 가진 시험 Controller를 강제 종료한 뒤, 독립 관찰자가 보유한 작업자·자식 핸들 모두에서 종료를 확인했다. 전역 슬롯을 다시 획득한 뒤에도 격리 시험 원장의 미확정 네이티브 실행 의도가 새 입장을 차단했다. 전용 계정의 생성 시 Job 편입, 정책과 결합된 활성 복구, 지정 프록시와 Windows DNS Client 경계는 미검증이다. 승인 대기 중 시스템 변경 및 온라인 모델 요청은 없었다. **P2.117 비활성 계정의 WFP 영속성과 복구 · REAL_PASS.** Windows 11에서 UAC로 승인한 설치기를 계정 활성화 직전에 강제 종료했다. 시험 계정의 비활성 상태와 Controller의 `CLEANUP_BLOCKED`를 확인했다. 별도 UAC로 실행한 복구기는 독립 BFE 세션에서 IPv4·IPv6 필터 16개가 유지된 것을 읽고 시험 소유 개체를 제거했다. 복구 후 Controller의 별도 조회에서 필터 16개, 공급자, 하위 계층, 시험 계정과 전용 디렉터리가 모두 없음을 확인하고 `CLEANUP_VERIFIED`를 기록했다. 앞선 비관리자 시험에서도 원장 기록 직후 Controller가 종료되면 차단이 남았다. 활성 작업자 강제 종료, 프록시·DNS·직접 송신 경계와 Codex 인증은 미검증이다. 이번 온라인 모델 요청은 0회다.

**P2.116 루프백 전용 관리자 시험 · PASS.** 사용자 승인 후 전용 표준 계정과 작업 디렉터리를 만들고 WFP IPv4·IPv6 필터 16개를 트랜잭션으로 설치했다. 독립 BFE 세션에서 필터를 읽은 뒤, 시험 계정의 두 허용 포트는 연결에 성공했고 두 차단 포트는 `WSAEACCES`를 반환했다. 호스트 양성 대조는 네 리스너 모두에 성공했다. 표준 토큰과 Job 회수를 확인하고 필터·하위 계층·공급자·계정·전용 디렉터리를 제거했다. 별도 조회에서 모두 사라졌음을 확인했다. 전역 방화벽 기본값은 변경하지 않았다. 외부 제공자 송신과 DNS 경계는 미검증이며 온라인 모델 턴은 시작하지 않았다.

**P2.116 네이티브 정책 설치 승인 대기 · BLOCKED.** Windows 11 Home의 현재 프로세스는 Administrators 그룹이 `DENY_ONLY`인 UAC 제한 토큰(`LIMITED`, 미승격)이다. `native-egress-preflight`는 이 사실을 현재 프로세스 토큰에서 조회하며 온라인 입장 상태를 바꾸지 않는다. WSL 기능은 활성화돼 있으나 Virtual Machine Platform은 비활성이고, 현재 계정에 등록된 WSL 배포판은 확인되지 않았다. 정책 설치·외부 송신 시험·모델 실행은 수행하지 않았다.

**P2.115 호스트 송신 · BLOCKED.** Windows 11 Home의 유효 방화벽 프로필은 기본 송신을 허용했다. 현재 실행 권한에서는 WFP 필터 컨테이너의 보안 설명자 조회와 빈 읽기/쓰기 트랜잭션 시작이 오류 `5`로 거부됐다. 소유 PowerShell 양성 대조군은 프록시 환경변수를 둔 상태에서 IPv4·IPv6 시험 리스너에 표식을 직접 전달했고, 별도 프록시 리스너에는 접속하지 않았다. 공식 App Server `0.167.1`의 MXC 명령은 동일 주소 계열에서 `10013`으로 거부됐다. 파일 경계와 고정 검증은 계속 통과했다. 이 관측은 명령 경계를 확인하며 호스트의 제공자 전용 송신은 `NOT_VERIFIED`로 유지한다. 모델 요청은 시작하지 않았다.

**P2.114 안정판 비중첩 명령 진단.** 공식 Windows x64 Codex `0.167.1` 배포 ZIP과 실행 파일을 고정하고, 합성 홈에서 App Server가 자체 MXC로 명령을 실행하는 경로를 확인했다. 읽기 프로필은 쓰기를 거부했고 쓰기 프로필은 허용했으며, 두 프로필에서 범위 밖 표식 읽기가 거부됐다. 자식의 작업 소유 루프백 연결은 `10013`으로 거부됐다. Controller가 지정한 고정 명령으로 합성 소스 두 개를 수정한 후 읽기 전용 검증은 종료 코드 `1`에서 `0`으로 바뀌었다. 소유 Job과 파이프를 회수했다. 호스트의 제공자 전용 송신과 모델 턴의 내장 도구 통제는 미입증이며 온라인 실행은 차단 상태다. 이 진단에는 모델 요청이나 제공자 사용량이 없다.

**P2.113 공식 Codex 실행 경계 실측.** Windows CLI `0.167.0-alpha.3.2`에서 ChatGPT 로그인 모드를 확인했다. 직접 MXC 명령은 합성 파일에 대한 읽기 전용·읽기/쓰기 프로필을 각각 집행했다. 그러나 오프라인 MXC 안의 공식 App Server `0.167.0`은 동일한 읽기 명령을 시작하기 전에 `NATIVE_MXC_UNAVAILABLE_ON_EXECUTOR`를 반환했다. 관리 네트워크 프로필은 작업 소유 루프백 연결을 허용했고 오프라인 프로필은 거부했다. 두 시험 모두 소유 Job을 회수했다. 온라인 공급자 전용 송신과 모델 내장 도구 권한은 각각 미입증이다. 모델 턴이나 구독 텍스트 폴백은 실행하지 않았다.

**P2.112 완료 기준과 반복 판정.** 통합 구독 세션은 사용자가 승인한 완료 기준 ID와 관측 연결을 승인 해시에 고정한다. Verifier가 해당 기준을 실제로 관측한 경우에만 `VERIFIED`를 부여한다. 개선과 퇴행을 각각 원장에 기록하고, 동일 복제본 상태나 정규화한 실패가 반복되면 한도 안에서 Manager가 다른 접근을 제안해야 한다. 미검증 기준이 남은 모델 완료 판정은 `USER_TEST_REQUIRED`로 보존한다. 온라인 Codex 코딩 에이전트의 실행 경계에는 P2.111의 차단 조건이 계속 적용된다.

**P2.111 실행 한도와 Windows 경계 재검토.** 구독 텍스트 세션에서 사이클 상한을 선택 사항으로 바꾸고 역할의 남은 시간과 모델 토큰을 시작 전에 확인한다. 실행 한도, 승인 만료, 제공자 한도와 미확정 응답을 구분해 기록한다. 독립 Git 복제본에서 공식 MXC 명령을 통해 승인 소스를 수정하고 테스트했다. Git 메타데이터·테스트 파일 쓰기, 외부 파일 접근과 루프백 접속은 거부됐다. 명령 Job은 모두 회수했다. 온라인 코딩 에이전트의 호스트 송신과 내장 도구 경계는 미입증이다.

**P2.110 세션 권한과 반복.** 통합 구독 세션에서 파일 읽기·수정, 고정 빌드·검증, 소유 창 조작·캡처, 증거 저장·정리의 역할별 범위를 승인 해시에 연결한다. 최종 Manager의 다음 작업과 재작업은 사이클·토큰·시간 한도 안에서 진행한다. 공식 CLI의 ChatGPT 로그인 상태를 확인했으며, 호스트 연결과 내장 도구 경계 미입증으로 자동 Codex 턴은 차단 상태다.

**P2.109 WinForms SDK 경로.** 승인된 앱을 MXC 안에서 실행하고 같은 Job의 소유 창만 조작한다. 구독 Verifier는 상태·선택·크기 및 창 캡처를 산출물 해시와 연결한다. 최종 Manager와 별도 원본 반영은 해당 시나리오의 실제 GUI 증거를 요구한다.

**P2.108 오프라인 SDK 프로젝트 검증.** Microsoft.NET.Sdk의 제한된 프로젝트 그래프와 콘솔 테스트를 실제 MXC에서 복원·빌드·실행한다. 라이브러리 C# 변경을 구독 개발과 원본 승인에 연결한다. 외부 NuGet 패키지, 사용자 MSBuild 코드, 프로젝트 구성에 대한 모델 쓰기, 삭제·이동은 승인 대상이 아니다.

**P2.107 기존 Git 프로젝트 연결.** 승인된 하위 파일 경로의 배치, 기존 Roslyn 격리 어댑터, 별도 승인된 원본 쓰기를 연결한다. 원본에 이미 수정·스테이징된 대상은 제외한다. Python 하위 파일의 AST 검증만으로는 원본 쓰기를 승인할 수 없다.

**P2.101 개발 환경 탐색 및 동적 .NET 승인.** 등록 복제본의 `global.json`을 읽어 실제 설치된 7.0.302 SDK, 7.0.5 런타임·참조 팩을 선택하고 MXC 콘솔 컴파일·실행을 재검증했다. 같은 버전을 선택하는 정책 변경도 기존 승인을 무효화했고, 미설치 SDK는 실행 전에 차단했다. 모델 변경 C# 및 자동 온라인 설치는 차단 상태다. Python·C++·Unity 환경은 표식 탐지까지만 제공한다.

**P2.100 승인된 C# 콘솔 빌드·실행 실측.** 등록된 독립 Git 복제본에서 검토된 C# 두 파일을 MXC의 .NET SDK 7.0.302와 Roslyn 4.6.0으로 컴파일했다. .NET 런타임 7.0.5에서 입력 두 건이 통과했고, 별도 기대값 불일치·취소·시간 초과도 Controller 원장에 기록했다. 컴파일러의 경계 밖 읽기와 입력 위치 쓰기, 실행 DLL의 경계 밖 읽기·쓰기와 루프백, 고정 자식의 경계 밖 읽기가 거부됐다. 각 단계의 소유 Job을 회수했다. 모델 변경 C#, 일반 MSBuild, C# GUI는 이 검증에서 제외된다.

**P2.99 실제 MXC 모듈 import·호출.** 독립 Git 복제본의 두 파일을 실제 구독 Developer가 변경했다. **P2.98 실제 MXC CPython 검증.** 독립 Git 프로젝트의 두 파일을 실제 구독 Developer가 수정했다. 승인된 고정 하네스가 Windows MXC에서 두 파일을 바이트코드로 빌드하고 실제 함수 관측 6건과 종료 코드 0을 기록했다. 같은 영수증으로 최종 Manager가 COMPLETED를 판정했다. 소스 쓰기, 바깥 표식 읽기·쓰기, 작업 소유 루프백 연결이 거부됐고 고정 자식에서 읽기 거부가 유지됐다. 별도 실제 실패·취소·시간 초과 실측에서 Job 회수를 확인했다. 일반 빌드 스크립트와 생성 EXE 실행은 미연결이다.

**P2.97 다중 파일과 GUI 자동 재작업 실측.** 실제 구독 세션에서 `clamp.py`와 `status.py`를 함께 수정해 파일별 정수 벡터를 통과했다. 별도 실제 WinForms 세션에서는 동결 기대값과 다른 상태를 캡처했고, 동일 승인으로 Developer가 한 번 수정한 뒤 재빌드·GUI PASS·최종 COMPLETED까지 진행했다. 두 번째 파일 적용 실패의 롤백과 명시적 새 파일 생성은 회귀 시험에서 확인했다. 일반 생성 코드 실행은 미연결이다.

**P2.93 승인된 한 파일의 실제 구독 Developer 수정.** P2.92의 실제 계획으로 등록 복제본의 \`sample.txt\` 변경을 확인했다. 별도 합성 Git 프로젝트에서는 실제 Manager 계획과 구독 Developer를 순차 실행해 \`greeting.py\` 한 파일을 변경했다. **P2.92 구독 텍스트 Manager.** 전용 브라우저 OAuth 동의와 구독 범위를 확인하고 공식 모델 목록을 조회했다. 운영 DB와 분리된 시험 프로젝트에서 실제 `gpt-6.1-sol` 스트림의 `response.completed`를 수신했다. 승인 범위에 맞는 계획을 보호 저장하고 Controller 원장에 완료 및 제공자 보고 사용량 1,256 토큰을 기록했다. 먼저 관측한 MIME 불일치 두 건은 UNKNOWN으로 유지한다. `text/plain` 응답도 SSE 프레임과 공식 완료 이벤트가 모두 확인되어야 완료할 수 있다. **P2.88 첫 구독 Manager 환경 판정 · BLOCKED.** 기존 `manager-mxc-offline`의 `--loopback-only` 진단은 공식 MXC 오프라인 프로필에서 작업 소유 TCP 리스너에 대한 직접 연결을 측정한다. Windows 11 Home에서 호스트 대조군은 연결됐고 격리 프로세스는 소켓 오류 `10013`으로 거부됐다. 소유 Job의 활성 프로세스는 0이었고 소켓과 진단 임시 디렉터리를 회수했다. 결과를 격리된 시험 원장에서 검증했다. 온라인 MXC 관리 네트워크는 루프백 허용이 필요하므로 오프라인 결과를 제공자 전용 연결의 근거로 사용할 수 없다. 다음 실행 후보는 호스트 루프백과 우회 경로를 별도로 제한하는 검증된 환경이다. 별도 VM을 사용하더라도 서버 내부 도구의 호출 전 차단은 독립적으로 입증해야 한다. 두 차단 조건을 유지했으며 구독 턴을 시작하지 않았다.

**P2.87 MXC 안의 App Server 호스트.** Windows 11 Home에서 관리자 변경 없이 공식 MXC로 서명 안정판 App Server `0.167.0` 자체를 감싸고 stdio 초기화와 정상 회수를 실측했다. 같은 오프라인 프로필의 고정 PowerShell 프로브는 작업 표식을 읽었고 작업 파일의 쓰기용 열기와 외부 보호 표식 읽기를 Windows 오류 5로 거부당했다. 두 표식의 해시는 유지됐다. `manager-mxc-offline`은 기존 단일 슬롯과 진단 의도·결과 원장을 사용한다. 이 증거는 제한된 파일 동작과 stdio에 한정되며, 공식 제공자만 허용하는 온라인 연결 및 서버 내부 도구 사전 차단은 미입증이다. 실제 구독 턴은 시작하지 않았다.

**P2.86 소유자 Manager 한 턴 진입점.** `manager-turn --project <ID> --binary <PATH> --cli-sha256 <SHA> --home <PRIVATE_HOME> --expires <UNIX_SECONDS>`는 요구사항·지침 해시, 바이너리, 원장 세대, 읽기 범위와 최대 60초 예산을 검토용으로 묶는다. 같은 인수에 `--approve <REVIEW_SHA256>`를 전달하면 기존 Controller 입장 검사와 단일 슬롯을 사용한다. 검토는 최대 5분 동안 유효하고 파일이나 원장 상태가 달라지면 다시 확인해야 한다. 서명 안정판에서 서명 확인과 승인 해시 재검증을 거쳤고 실행 경계에서 차단됐다. Manager에게 Developer의 복제본 쓰기·명령·GUI 권한을 부여하지 않는다. 호스트 제공자 연결과 서버 내부 도구의 호출 전 통제는 여전히 입증이 필요하다.

**P2.85 Manager RPC 송신 범위.** Controller는 Manager 정책 검사, 스레드 검사, 계획 턴에 서로 다른 stdio RPC 허용 목록을 첫 쓰기 전에 고정한다. 서명된 안정판 App Server `0.167.0`에 연결한 검사에서 명령 실행·파일 쓰기·계정 조회·턴 시작 RPC가 파이프 쓰기 전에 거부됐고 초기화는 정상 종료했다. 이 경계는 Controller의 송신 권한을 제한한다. App Server 내부 도구 호출 전 차단과 호스트의 공식 제공자 연결 제한은 여전히 미입증이며, 실제 구독 턴은 시작하지 않았다.

**P2.84 Manager 관리 정책 호환성.** 설치된 서명 CLI `0.167.0-alpha.3.2`와 보관된 공식 App Server `0.167.0`에서 임시 무인증 홈으로 실제 설정을 조회했다. 두 후보 모두 유효 설정이 `read-only`와 `never`였고, 관리 요구사항에서 확인된 로그인 허용 목록이 ChatGPT를 허용했다. Controller는 관리 요구사항의 존재만으로 차단하지 않고 승인 계약에 적용되는 허용 목록과 기능 설정을 확인한다. 충돌과 해석할 수 없는 활성 조건은 계속 차단한다. 설정 호환성은 호스트의 제공자 연결 제한 또는 서버 측 부작용 도구 차단의 증거로 승격하지 않는다. 두 조건 모두 여전히 미입증이므로 모델 턴은 시작하지 않았다.

**P2.83 Manager 사전 검사.** 설치된 서명 CLI `0.167.0-alpha.3.2`의 `login status`에서 ChatGPT 로그인 모드를 확인했다. 동일 이미지에서 오프라인 계정·턴·동적 도구 스키마를 생성했다. 별도 임시 홈의 App Server 설정 RPC는 `read-only`, `never`와 비어 있지 않은 관리 요구사항 응답을 보고했다. 현재 Manager 계약은 해당 요구사항을 검증할 수 없어 계정·스레드·턴 RPC 이전에 거부한다. App Server 호스트의 공식 제공자 연결 제한과 호출 전 부작용 도구 차단도 여전히 미입증이다. `manager-preflight --project <ID>`와 개발 시작 화면은 실행 없이 차단 사유를 표시한다. 실제 구독 턴은 시작하지 않았다.

Manager 수신 경로는 중복 이벤트와 도구 요청을 거부하고, 계약에 맞는 종료 응답 및 Job·파이프 회수 후에만 지침 해시와 정제된 턴 영수증을 원장에 기록한다. 공개 공통·역할 지침은 로컬 해당 층이 없을 때 해시로 고정할 수 있다. 실측은 서명 CLI의 설정·스키마에 한정되며 계획 수신·회수·불명확 결과 차단은 테스트 피어에서 검증했다.

**P2.82 독립 GUI 테스트 EXE.** Controller가 고정 C# 소스에서 컴파일하고 출처를 기록한 WinForms x64 EXE를 등록 복제본에서 선택할 수 있다. 실행 승인에 EXE·시나리오 해시, 역할, 세대, 작업·세션·취소 식별자와 인자·작업 디렉터리 정책·예산을 묶는다. 실행기는 해시가 일치한 EXE를 비공개 임시 작업 디렉터리에 복사하고, 소유 창의 컨트롤과 네이티브 메뉴를 검증한다. 감사 원장은 실행·이미지·Job 회수를 기록한다. 이 경로는 검토된 테스트 실행 파일에 한정한다. 임의 EXE와 실시간 모델 도구 연결은 계속 차단한다.

**P2.81 등록 프로젝트의 선언형 GUI 시나리오.** Controller가 등록된 작업 복제본의 `gui-test.json` 해시, 프로젝트 개정, 역할 예산과 시스템 실행기 해시를 승인에 묶는다. Developer·Reviewer·Verifier의 소유자 승인 실행과 Manager의 영수증 열람 경계를 적용한다. 프로젝트별 합성 입력과 컨트롤 별칭으로 실제 WinForms 창을 검증하고 P2.80 이미지 보고서와 Job 회수를 재사용한다. 임의 프로젝트 EXE·빌드 명령과 모델 호출은 아직 차단된다.

**P2.80 고정 GUI Verifier.** 소유자가 승인한 고정 WinForms 시나리오를 Controller가 실행한다. Job에 편입한 PowerShell의 PID, UI 스레드, 최상위 창을 확인한 뒤 대상 컨트롤에만 제한된 Win32 메시지를 전달한다. 클릭·입력·스크롤·리사이즈 관측과 종료 코드·Job 회수·이미지 해시를 원장에 연결한다. Command Center에서 대표 3장과 원본·가공본·전후 비교를 확인할 수 있다. 승인된 테스트의 고정 데이터에 한정되며 프로젝트 EXE 실행, 모델 역할의 GUI 도구, 실자동 App Server는 여전히 차단된다.

**P2.78.** 일반 모드는 승인된 구독 인증·공식 제공자 연결·작업 범위 내 도구 사용을 전제로 한다. 완전 오프라인 실증, Windows 게스트 및 강화 A/B/C는 별도다. 일반 모드에서도 다른 앱 접근 및 범위 밖 파일·명령을 막는 집행, 단일 슬롯·회수·감사가 필수다.
