# 시각 디자인 검토와 구조 변경 검증

## 구현 전

- 기존 실제 화면에서 조작·정보 위계·결함을 확인하고 동일한 제품 기능으로 후보를 비교한다. 목표가 확정되지 않은 큰 시각 변경은 검토 가능한 이미지와 대상 해상도를 먼저 고정한다.
- 시안, 기존 제품 캡처, 구현 후보 캡처에 각각 출처·규격·버전을 연결한다. 생성 아트와 외부 소재의 출처·사용 조건을 기록한다.
- 시안 검토 판정과 사용자의 디자인 선택을 따로 기록한다. 사용자 선택이 필요한 사이클은 기존 제품 변경 전에 승인 상태를 확인한다.
- 화면별 개성, 사용 가능한 공통 구성 요소와 스타일, 유지할 역할별 실루엣 및 접근성 표현을 명시한다.

## 구현과 검증

- 화면·시각 객체가 소유하는 표시와 상호작용, 도메인이 소유하는 계산과 상태, 실행 진입점이 소유하는 화면 전환을 명시한다. 기존 도메인 로직을 유지하면서 실제 호출되는 화면을 점진적으로 전환한다.
- 재사용 요소는 두 번째 사용처 또는 실제 편집 필요를 기준으로 결정한다. 부모 확장 정책, 최소 크기, 실제 렌더 경계와 가시 범위를 따로 기록한다.
- 후보의 실제 실행에서 정상 진입, 조작 및 복귀를 확인한다. 기존 동작을 유지하는 구조 변경에는 전후 기능 및 렌더 회귀 증거를 사용한다.
- 미적 평가에는 위계·가독성·일관성·표현 품질을 기록한다. 기능 평가는 사용 경로·포커스·입력·지역화·배치·검증된 결과를 기록한다.
- 작업 계약의 핵심 차이를 수치 또는 실제 화면 요소로 대조한다. 동일 증거의 반복 검토는 현재 후보에 유효한 경우 인수인계하고, 변경에 직접 영향을 받은 영역을 재검증한다.

이 절차의 제품별 적용 사례는 [MRGame UI 설계](https://github.com/RuinaR/MRGame/blob/a97c5524cce2c230c1d746f385a8f7373daec4d8/docs/design/UI-DESIGN.md)를 따른다.
