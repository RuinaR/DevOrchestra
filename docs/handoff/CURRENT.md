# DevOrchestra 동결 및 재개 안내

2026-11-18 소유자 결정으로 MRGame은 Codex 직접 개발로 전환했다. DevOrchestra는 소스, 승인·원장·복구 기록과 검증 근거를 보존하고 신규 자동 역할 실행을 동결한다.

- 로컬 두 원장에서 신규 실행 진입 차단을 검증했다. 운영 원장은 `RECOVERY_REQUIRED`로 유지한다. 종료 요청의 대기 한도가 만료됐으며, 별도 진단에서 소유 실행 미결 항목과 보류 Git 게시가 없음을 확인했다. 기존 UNKNOWN 기록을 보존한다. 로컬 체크아웃 원장은 `READY`다.
- 공개 제품 코드 기준은 [cd78d85](https://github.com/RuinaR/DevOrchestra/commit/cd78d85886bd4802a0232c81248db28d9544311e), 동결 전 공개 인수인계 기준은 [81c5766](https://github.com/RuinaR/DevOrchestra/commit/81c5766b7c4786edf3b16b0f3d1dad4346006ac9)이다. 로컬 개발 `8379c0056dff9` 및 운영 소스 `a6f91d4d5641`에는 별도 미게시 변경이 있다.
- 소스·패치·Git 번들·운영 지침 `public-v12`·원장 사본과 고유 자료는 비공개 보관을 검증했다. 배포 상태와 통합 회귀를 입증하지 못한 로컬 변경은 공개 main에 병합하지 않았다. 로컬의 시각 응답 줄 분할 및 게시 계보 인수 개선과 공개 제품 기능을 구분한다.
- MRGame의 경로 전환으로 동결된 등록 경로에는 이전 절대 경로가 남아 있다. 원장과 승인 원본은 그대로 보존한다. 자동 개발 복귀에는 소유자 명시 결정, 작업 트리 독점 확인, 로컬 보관 검증, 현재 경로로 별도 등록·승인, 운영 원장 복구와 실제 소유 Job 검증이 필요하다. 과거 경로 또는 승인으로 자동 재실행하지 않는다.
- [MRGame 직접 개발 인수인계](https://github.com/RuinaR/MRGame/blob/main/docs/handoff/CURRENT.md)에서 제품 상태와 다음 작업을 확인한다.

## 실행과 재개

1. [README](../../README.md)의 포터블 패키지 및 공식 Codex 초기 설정을 따른다. 빌드·검사는 [Windows 릴리스 QA](../WINDOWS-RELEASE-QA.md)를 확인한다. 로컬 운영 기능을 재현하려면 해당 실행의 실제 소스·도구·지침 해시가 필요하다.
2. 프로젝트·브랜치·원격 SHA·작업 트리를 확인한다. 등록부에 연결된 목표와 완료 기준, 승인된 파일·명령·예산, 현재 할당량을 다시 확인한다.
3. 기존 실행, 회수되지 않은 Job, 미확정 요청, 보류 후보와 게시 영수증을 확인한다. 충돌 또는 소유권 불명 상태는 기존 승인 복구 경로에서 처리한다. 기존 UNKNOWN은 보존한다.
4. 동일 제품을 수정하기 전에 이미 통과한 항목과 남은 확인 사항을 구분한다. 구조 변경은 인스턴스·콜백·실행 증거를, 시각 변경은 전후 이미지와 선택된 목표 시안을 대조한다.

## 마지막 확인 작업

MRGame 인카운터 선택·결과의 아트 가시 크기와 동작을 복구했다. 정식 시각 검토 및 후보 검증 후 제품이 게시됐다. Windows 릴리스에서 비활성 휴식, Esc, 측량 비용 3→1, 지원 건너뛰기, 강화 확정 및 두 번째 전투 진입을 관찰했다. 결정적 원정 검사 20,272개 단언과 정상 속도 플레이 관찰은 서로 독립된 결과다. 갤러리 37개에는 재사용 캡처가 섞여 있다. C6 등 사용자 테스트 판정의 범위는 [MRGame 개발 상태](https://github.com/RuinaR/MRGame/blob/a97c5524cce2c230c1d746f385a8f7373daec4d8/docs/development/CURRENT.md)를 확인한다.

## 재개 우선순위

1. 인카운터 씬을 실제 진입점에서 점진적으로 인스턴스화하고 아트 크기·포커스·네 경로·저장·전투를 검증한다.
2. 사용자가 선호한 마름모·삼각형·괄호형 실루엣과 얇은 공전선으로 다음 MRGame UI 시안을 검토한다. 화면별 디자인 확정 상태는 개별로 기록한다.
3. 공개 main과 로컬 운영 소스의 기능 차이는 각각 검증 가능한 변경으로 분리한다. 이 문서의 상태보다 최신 실행 영수증과 [프로젝트 개발 기록](https://github.com/RuinaR/MRGame/tree/main/docs/development)을 우선한다.
